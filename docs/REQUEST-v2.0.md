# Knock Market REQUEST v2.0

작성일: 2026-05-27

## Problem 1-Pager

### 배경

Knock Market은 그룹형 중고거래 장터에서 개인 판매자가 자신의 물건 매대를 만들고 지인에게 링크로 공유하는 개인형 거래 서비스로 전환한다.

### 문제

기존 코드에는 그룹, 차단, 평판, 상품 카테고리처럼 현재 제품 플로우에서 사용하지 않는 스키마와 API가 남아 있었다. 이 필드들은 신규 기능의 의미를 흐리고, 프론트/백엔드 DTO와 테스트를 불필요하게 복잡하게 만든다.

### 목표

- 상품은 판매자 개인(`member_id`)의 매대에만 속한다.
- 상품 상세 URL은 내부 숫자 ID를 노출하지 않고 추측하기 어려운 공개 식별자(`publicId`)를 사용한다.
- 판매자는 상품을 등록하고 픽업 위치를 지정한 뒤 만료 가능한 공유 링크를 만든다.
- 링크를 받은 사용자는 판매자의 공개 매대와 상품 상세를 보고 예약 의사를 남긴다.
- 알림은 예약 생성/승인/완료처럼 실제 거래 이벤트 중심으로 동작한다.
- 사용하지 않는 그룹/차단/평판/카테고리 스키마와 API를 코드에서 제거한다.

### 비목표

- 운영 DB 마이그레이션 자동화는 이번 범위에 포함하지 않는다. 현재 변경은 로컬 스키마 재생성 기준으로 검증한다.
- 실시간 SSE/푸시 알림과 상세 분석 대시보드는 별도 고도화 항목으로 둔다.
- 카카오 소셜 로그인 구현은 별도 작업으로 둔다.

### 제약

- 비밀값은 코드/문서/로그에 남기지 않는다.
- `NAVER_MAP_CLIENT_SECRET`, `NAVER_SEARCH_CLIENT_SECRET`는 백엔드 환경변수로만 사용한다.
- 공유 링크의 공개 응답은 판매자 공개 프로필, 상품 공개 정보, 거래 위치만 포함한다.

## 현재 제품 흐름

1. 판매자가 회원가입/로그인한다.
2. 판매자가 상품명, 설명, 거래 유형, 가격, 사진, 픽업 위치를 입력한다.
3. 상품은 판매자의 개인 매대에 저장되고, 외부 URL용 `publicId`가 발급된다.
4. 판매자가 개인 매대에서 만료 가능한 공유 링크를 생성한다.
5. 판매자는 구글 드라이브 일반 액세스처럼 현재 공유 링크 1개의 클릭 수, 사용 수, 활성 상태를 확인하고 필요하면 공유를 중단한다.
6. 지인이 공유 링크로 접속해 상품을 확인한다.
7. 지인이 상품에 예약을 요청한다.
8. 판매자는 알림과 예약 목록에서 관심/예약 상태를 확인하고 승인 또는 완료 처리한다.

## 제거된 모델과 스키마

| 영역 | 제거 항목 | 이유 |
|---|---|---|
| 그룹 장터 | `Group`, `GroupMember`, `GroupRepository`, `item.group_id` | 개인 매대에서는 상품 소유 기준이 판매자 `member_id` 하나로 충분하다. |
| 회원 차단 | `MemberBlock`, 차단 API, 차단 프론트 화면 | 현재 공유 링크 기반 지인 거래 플로우의 핵심 경로가 아니다. |
| 평판/매너온도 | `mannerTemperature`, `ReputationService`, `ReputationPolicy` | 프로필에서 노출하지 않고 거래 완료 플로우와도 분리되어 있었다. |
| 상품 카테고리 | `ItemCategory`, `item.category`, API/프론트 `category` 필드 | 등록 UI에서 이미 숨겨져 있었고 개인 매대 탐색 가치가 낮다. |

## 유지되는 기능

- 이메일/비밀번호 로그인과 Google OAuth 로그인
- 개인 매대(`/seller/:memberId`)와 공유 링크 매대(`/shop/:token`)
- 상품 등록/목록/상세/삭제
- 상품 상세 URL `/item/{publicId}` 공개 조회. 예약/북마크 같은 사용자 액션은 로그인 리다이렉트
- Naver Map 기반 픽업 위치 검색과 좌표 저장
- 찜, 예약, 알림, 후기 API
- 이미지 업로드
- 공유 링크 유효시간 선택: 1시간, 24시간, 무제한
- 단일 공유 링크 지표: 클릭 수, 사용 수, 활성/중단 상태
