# 서비스 기획안 – Knock Market 개인형 판매 페이지

## 1. 서비스 개요

> **“판매자가 카카오톡/인스타그램으로 공유하는 개인 중고마켓 페이지”**  
> 판매자는 자기 물건을 한 페이지에 모아 공유하고, 구매자는 링크로 들어와 물건과 Naver Map 기반 픽업 위치를 확인한다.

### Problem 1-Pager (2026-04-14)

- 배경: 기존 화면은 `Groups`, `Join First Group`처럼 그룹 가입이 첫 행동으로 보였다.
- 문제: 개인형 판매 서비스로 포지셔닝하려면 그룹 탭/카테고리/수동 주소 입력이 핵심 흐름을 흐린다.
- 목표: 개인 판매 페이지, 만료 가능한 공유 링크, Naver Map 기반 위치 선택, 카테고리 없는 등록 UX로 전환한다.
- 비목표: 이번 변경에서 `ItemCategory` DB enum과 기존 그룹 테이블을 물리적으로 제거하지 않는다.
- 제약: 기존 상품/예약 스키마의 `group_id` FK는 유지하고, 회원 생성 시 만들어지는 개인 그룹을 내부 저장 경계로 사용한다.
- 대안 비교:
  - A안: 그룹/카테고리 도메인을 DB에서 즉시 삭제. 포지셔닝은 가장 선명하지만 예약/북마크/문서/마이그레이션 영향이 크다.
  - B안: UI/API는 개인형으로 바꾸고, 내부 호환을 위해 개인 그룹과 기본 `ETC` 카테고리를 사용. 영향도가 작고 빠르게 검증 가능하다.
- 선택: B안. 사용자 경험은 개인형으로 바꾸되 데이터 모델 제거는 별도 마이그레이션으로 분리한다.

## 2. 핵심 사용자 흐름

1. 판매자가 로그인한다.
2. 상품명, 설명, 가격, 사진을 입력한다.
3. Naver Map에서 픽업 위치를 검색하거나 지도에서 직접 선택한다.
4. 상품은 판매자의 개인 그룹에 내부 저장되고, UI에는 카테고리/그룹 선택이 노출되지 않는다.
5. 판매자가 내 판매 페이지에서 만료 시간을 선택해 공유 링크를 만든다.
6. 카카오톡/인스타그램으로 `/shop/{token}` 링크를 공유한다.
7. 구매자는 링크로 판매자의 물건 목록을 보고 상세에서 예약한다.

## 3. 현재 구현된 범위

- 홈 화면은 개인 판매자 중심 마켓으로 변경했다.
- 하단 탭의 `Groups`를 제거하고 `Market`으로 교체했다.
- 상품 등록 화면에서 그룹 선택과 카테고리 선택을 제거했다.
- 상품 생성 API는 `groupId`가 없으면 판매자의 개인 그룹을 사용한다.
- 상품 생성 API는 `category`가 없거나 UI에서 숨겨져도 기본 `ETC`로 저장한다.
- 판매자 공유 링크 API를 추가했다.
  - `POST /api/v1/seller-shares`
  - `GET /api/v1/seller-shares/{token}`
- 공유 링크는 `InviteDuration`을 재사용해 5분/30분/1시간/1일/영구 만료를 지원한다.
- Naver Map Client ID가 있으면 등록 화면에서 지도 선택과 geocode 검색을 사용할 수 있다.
